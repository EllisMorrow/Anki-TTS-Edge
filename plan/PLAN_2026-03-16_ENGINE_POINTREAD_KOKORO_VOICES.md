# Anki-TTS-Edge 修复与增强计划 (2026-03-16)

> 目标：把“在线/离线引擎切换、点读、离线音色列表”做成稳定可用的工业化链路，并把排障信息固化到仓库，避免聊天窗口丢失后无法继续。

## 1. 背景与现状

### 1.1 项目定位
- 桌面端工具：输入文本 -> 生成语音 -> 播放/历史管理/剪贴板联动。
- UI：Flet (Python)。
- 两套 TTS 引擎：
  - 在线：Microsoft Edge TTS（`edge-tts`）。
  - 离线：Kokoro v1.1（通过 `sherpa-onnx` 离线 TTS 可执行文件，`--sid` 选择音色）。

### 1.2 当前架构要点（已落地）
- Provider 抽象：`TTSManager` 根据 `settings.tts_engine` 选择 `EdgeTTSProvider` 或 `LocalKokoroProvider`。
- 离线引擎管理：`LocalEngineManager` 负责下载/校验/安装/健康检查（模型与运行时落在 `%APPDATA%\\Anki-TTS-Edge\\providers\\kokoro\\...`）。
- 时间戳/点读：在线引擎产出逐词边界（words/sentences）；离线引擎 v1 暂不产出时间戳（words/sentences 为空，接口已预留）。

## 3. 根因假设（用于指导调研）

### 3.1 引擎切换“在线但仍像本地”
- 可能并非真的调用了本地引擎，而是：
  - 切换引擎后仍在播放“上一次生成的缓存音频文件”（不会自动重新生成）。
  - UI 的声音列表与当前引擎不一致，导致用户误判当前链路。
- `debug_edge_tts_internal_error` 多数来自 `edge-tts` 内部异常（网络/voice 不合法/服务端返回异常）。

### 3.2 点读失效
- 离线：时间戳为空属于“能力缺失”，应明确提示“不支持点读”而不是静默失败。
- 在线：点读依赖播放器 seek 能力；当前用 `pygame.mixer.music.play(start=...)` 可能在 mp3 上不稳定，导致跳转不生效。

### 3.3 离线音色列表
- 我们当前离线模型：`kokoro-int8-multi-lang-v1_1`，音色通过 `--sid` 选择（0-102）。
- 模型包并不自带可读的“音色列表文件”，需要我们在程序侧生成/内置一个 voice catalog（至少包含 sid、显示名、分组）。
  - 参考官方示例页映射：`af_*` (美式女声, sid 0-1)、`bf_*` (英式女声, sid 2)、`zf_*` (中文女声, sid 3-57)、`zm_*` (中文男声, sid 58-102)。
  - 由于 zf/zm 的编号并非连续（例如 `zf_017`、`zm_095` 等），必须按官方映射表固化，而不是用 `zf_001..zf_055` 这种“顺推生成”。

- [ ] 声音页按引擎展示：
  - 在线：展示微软声音列表（现状）。
  - 离线：展示 Kokoro v1.1 的 sid 音色列表（替代“微软列表 + sid 输入框”的混乱状态）。
- [ ] 选择逻辑分流：
  - 在线：点击列表 -> 更新 `selected_voice_left/right`。

验收：

- 在线声音列表可选；Edge 失败时能给出明确错误原因（或可重试/提示网络问题）。
